Multi-turn continuity = `previous_interaction_id`; extend via `task: "extend"`. 3–10s/clip, 720p for v1 | Verified against ai.google.dev/gemini-api/docs/omni (post–Jan-2026, after model knowledge cutoff). | 2026-09-07 | Generation runs as one long Cloud Run request (`--timeout 3600`), writing progress to a Firestore `generations/<jobId>` doc; clips stored private in Cloud Storage and streamed back via `GET /api/clips/:jobId/:part` | Single-user, low volume — a full job queue is overkill; long request + job doc for reload recovery is enough. | 2026-09-07 | Reference images passed to Omni Flash inline as base64 (not a public URL / Files API upload); scraper runs inline in `POST /api/scrape` (not a Cloud Run Job) | Images are small; base64 avoids a public-URL dependency with locked-down Storage. Inline scrape is fine for the 1–3-model manual trigger; `jobs/scraper` reserved for a scheduled full-list refresh (P2.4) | Claude Code |
| 2026-09-07 | cardekho.com scrape: plain `fetch` of `/<brand>/<model>/pictures` + regex over `stimg.cardekho.com/images/car{exterior,interior}images/...` — no headless browser | Spike 2026-09-07: image URLs (incl. named angles `front-left-side`, `rear-left-view`, interior `dashboard`) are in the initial HTML. Resolves the second Phase 1 spike | Claude Code |
| 2026-09-07 | Omni Flash extend calls send ONLY `previous_interaction_id` (no `generation_config.video_config.task`) | The Interactions API errors "previous_interaction_id is not allowed when video task is set" — the extend/continue intent is implied by the prior interaction. First multi-part test surfaced this | Claude Code |
| 2026-09-07 | Long videos: NO extend at all. Independent `create` per segment, ffmpeg-stitched. Segments 2+ seeded with the previous segment's last frame via `image_to_video` | `extend` only accepts a source ≤ ~10s (18s→27s fails "invalid argument"), and continuity via `previous_interaction_id` was weak anyway. Frame-seed + strong prompt keeps character/car/setting across the cut; tested consistent with CarDekho refs attached | Santosh |
| 2026-09-07 | Omni Flash `input` array: text item is `{type:'text', text:...}` (not `data`); `image_to_video` accepts at most 2 images | Both surfaced as live API errors during multi-segment testing | Claude Code |
| 2026-09-07 | App restructured into 5 sections (Projects, Clients, Cars, Actors, Global Instructions) for the design team, not just Santosh | Matches the original Excalidraw workflow: two persistent layers (Universal Settings + Client Info & Docs) with per-project state on top. Libraries are built once and reused | Santosh |
| 2026-09-07 | Access: single shared team password (no per-user identity) | Chosen over Google sign-in + allowlist for speed; the tradeoff accepted is no 'created by' attribution on projects. HMAC bearer token, 30d TTL, `APP_PASSWORD` secret; the sentinel 'unset' means the gate is open and the UI shows a warning banner | Santosh |
| 2026-09-07 | Client GMB import uses the Google Places API (New), not HTML scraping of Maps | Legitimate and reliable; Maps renders in JS so scraping would be brittle and against ToS. Costs a small amount per lookup | Santosh |
| 2026-09-07 | Car library hierarchy: Brand → Model → Variant → Colour | CarDekho publishes images per model + colour, so variants inherit the model angle set and carry their own spec/price. Colour name AND hex come free in the swatch filename | Santosh |
| 2026-09-07 | Projects compose into the existing `Brief` via `composeBrief()` rather than the pipeline reading library records directly | Keeps buildPrompt / runChecks / estimateCost / the generation loop completely unchanged — one integration point instead of rewriting the engine | Claude Code |
