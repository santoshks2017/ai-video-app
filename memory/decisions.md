| 2026-09-07 | Omni Flash extend calls send ONLY `previous_interaction_id` (no `generation_config.video_config.task`) | The Interactions API errors "previous_interaction_id is not allowed when video task is set" — the extend/continue intent is implied by the prior interaction. | 2026-09-07 | Long videos: NO extend at all. Independent `create` per segment, ffmpeg-stitched. Segments 2+ seeded with the previous segment's last frame via `image_to_video` | `extend` only accepts a source ≤ ~10s (18s→27s fails "invalid argument"), and continuity via `previous_interaction_id` was weak anyway. Frame-seed + strong prompt keeps character/car/setting across the cut; tested consistent with CarDekho refs attached | Santosh |
| 2026-09-07 | Omni Flash `input` array: text item is `{type:'text', text:...}` (not `data`); `image_to_video` accepts at most 2 images | Both surfaced as live API errors during multi-segment testing | Claude Code |
| 2026-09-07 | App restructured into 5 sections (Projects, Clients, Cars, Actors, Global Instructions) for the design team, not just Santosh | Matches the original Excalidraw workflow: two persistent layers (Universal Settings + Client Info & Docs) with per-project state on top. Libraries are built once and reused | Santosh |
| 2026-09-07 | Access: single shared team password (no per-user identity) | Chosen over Google sign-in + allowlist for speed; the tradeoff accepted is no 'created by' attribution on projects. HMAC bearer token, 30d TTL, `APP_PASSWORD` secret; the sentinel 'unset' means the gate is open and the UI shows a warning banner | Santosh |
| 2026-09-07 | Client GMB import uses the Google Places API (New), not HTML scraping of Maps | Legitimate and reliable; Maps renders in JS so scraping would be brittle and against ToS. Costs a small amount per lookup | Santosh |
| 2026-09-07 | Car library hierarchy: Brand → Model → Variant → Colour | CarDekho publishes images per model + colour, so variants inherit the model angle set and carry their own spec/price. Colour name AND hex come free in the swatch filename | Santosh |
| 2026-09-07 | Projects compose into the existing `Brief` via `composeBrief()` rather than the pipeline reading library records directly | Keeps buildPrompt / runChecks / estimateCost / the generation loop completely unchanged — one integration point instead of rewriting the engine | Claude Code |
| 2026-09-07 | **Reversed** the 2026-09-06 split: all 9 use cases are now automated, none are prompt-only | The split assumed no model could lip-sync a presenter from a photo. Omni Flash does — the first real generations produced a presenter speaking Hindi to camera convincingly. The `presenter` mode stays in the type so a future category or provider can opt out | Santosh |
| 2026-09-07 | Footer bar, dealer + brand logos and the end card are COMPOSITED IN POST (ffmpeg + SVG→PNG via sharp), never generated. The prompt carries a CLEAN FRAME instruction telling the model to leave that furniture out | The model garbles small text, invents manufacturer badges, and ended videos on stray car shots. Compositing makes them exactly right and guarantees the video ends on dealer details + CTA. Overlays sit on top, so anything the model drew would show through at the edges — hence the explicit instruction | Santosh |
| 2026-09-07 | Segments crossfade (0.5s, video + audio) instead of hard-cutting | Hard cuts between independently-generated clips read as restarts | Santosh |
| 2026-09-07 | Scene planning rewritten: fit scene count to duration against a real floor (4.5s spoken), select beats round-robin across use cases, weight durations across the whole timeline, pack into the fewest segments the model's cap allows | Concatenating every beat of every use case made long videos rushed and lumpy — 50s/3 use cases was 12 scenes of ~4s with segment lengths from 4.2s to 10.0s. Now 10 scenes of 4.2–5.8s in 5 even 10.0s segments | Santosh |
| 2026-09-07 | Project editor leads with duration/aspect/model only; narration, on-screen text, end card and look are behind disclosures, storyboard collapsed | Too many visible choices confused the primary path, which is "pick requirements, get a video" | Santosh |
| 2026-09-07 | Segments are packed around scene durations (whole scenes only, up to the model cap) rather than scenes being stretched to fill fixed-length segments. Two scenes overrunning the cap by <9% stay together and are trimmed | Sizing segments first distorted the pacing the scene weighting had just set, and could cut mid-action. The squeeze allowance keeps 50s at 5 segments instead of 7 — an imperceptible trim beats a paid call plus an extra cut | Santosh |
| 2026-09-07 | Every generation is filed against its project (`generations.projectId`) with a poster frame, cost, and specs; spend rolls up onto the project | Regenerating used to bury the previous run — clips survived in Storage but nothing surfaced them. History also gives per-video cost and a project/portfolio spend total | Santosh |
| 2026-09-08 | Overlay text is wrapped and shrunk to fit by a layout pass in `post.ts` (estimated glyph advances → word wrap → step font size down); footer ≤2 lines, end-card name ≤3 | SVG text neither wraps nor shrinks, so a full postal address and a legal entity name ran off both edges of the frame | Santosh |
| 2026-09-08 | `ClientProfile.displayName` — short trading name used on screen, distinct from the full listing name. `suggestDisplayName()` proposes one and the GMB import pre-fills it | Google listings return names like "Tata Motors Cars Showroom - Jasper Cars Private Limited, Malviya Nagar"; no overlay can carry that, and layout alone can't fix it | Santosh |
| 2026-09-08 | `ClientProfile.footerText` — the contact strip is saved per client, not derived per project | Derived per project it could drift between videos for the same client, with nowhere to correct it once. Project settings now show it read-only and point at the client | Santosh |
